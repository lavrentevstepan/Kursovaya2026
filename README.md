## 📌 Краткое описание проекта

**SecureKnowledgeBase (SKB)** — защищенная локальная система управления корпоративной базой знаний с интеллектуальным вопросно-ответным RAG-ассистентом (Retrieval-Augmented Generation).

### Ключевой функционал:
1. **Управление документами и файловое хранилище:**
   - Поддержка форматов `.txt`, `.md`, `.pdf` (через локальный парсер `PdfPig`) и `.docx` (через потоковый XML ZipArchive).
   - Защита от **Path Traversal**, расчет хеш-сумм **SHA-256** для контроля целостности, изоляция файлов вне публичного веб-корня.
2. **Многоуровневое разграничение доступа (RBAC & Clearance Levels):**
   - Уровни доступа: `PublicInternal` (1), `Restricted` (2), `Confidential` (3).
   - Пользователь видит только те документы и фрагменты, которые не превышают его максимальный уровень допуска.
3. **Полнотекстовый поиск и чанкинг:**
   - Интеллектуальная фрагментация текстов на чанки по 300–600 символов с наложением перекрытий и фиксацией заголовков разделов.
   - Локальный взвешенный поисковый движок с нормализацией русской и английской морфологии (стемминг) и строгой фильтрацией по правам доступа.
4. **Интеллектуальный RAG-Ассистент:**
   - **Детерминированный извлекательный режим (Extractive QA):** синтез ответов и точных цитат за ~8 мс без необходимости в GPU и нейросетях.
   - **Интеграция с локальной LLM (Ollama):** поддержка локального инференса (`http://localhost:11434`, модели `qwen2.5:1.5b` / `llama3.2:1b`) с защитой от Prompt Injection.
   - **Отказоустойчивость (Graceful Fallback):** автоматическое переключение на извлекательный режим при выключенной или недоступной LLM.
   - **Исключение галлюцинаций:** при отсутствии подтвержденных данных в базе ассистент возвращает безопасный ответ: *«Точный ответ в доступной базе знаний не найден.»*
5. **Неизменяемый аудит безопасности:**
   - Журналирование всех операций: вход/выход, загрузка, удаление, скачивание, поисковые запросы, обращения к ассистенту и попытки несанкционированного доступа (`AccessDenied`).

## 🚀 Быстрый запуск в ручном режиме

### Требования к окружению:
- Операционная система: **Windows 11** (x64)
- Установленный **.NET 8 SDK** (версия 8.0.x)
- Свободное дисковое пространство: от 500 МБ
- ОЗУ: от 4 ГБ (для режима Extractive QA) или от 8 ГБ (при включенной локальной LLM)

### Шаги запуска:

1. **Клонирование репозитория и переход в папку проекта:**
   ```bash
   git clone git@github.com:lavrentevstepan/Kursovaya2026.git
   cd Kursovaya2026
   ```

2. **Сборка решения:**
   ```powershell
   dotnet build SecureKnowledgeBase.sln
   ```

3. **Запуск модульных тестов (48 тестов):**
   ```powershell
   dotnet test SecureKnowledgeBase.sln
   ```

4. **Запуск веб-приложения:**
   ```powershell
   dotnet run --project src/SecureKnowledgeBase.Web --urls "http://localhost:5000"
   ```

После запуска приложение доступно в браузере по адресу:  
👉 **[http://localhost:5000](http://localhost:5000)**

## 🔐 Учетные записи по умолчанию

При первом запуске база данных автоматически инициализируется следующими тестовыми учетными записями:

| Логин | Пароль | Роль в системе | Максимальный уровень допуска | Описание прав |
| :--- | :--- | :--- | :--- | :--- |
| **`admin`** | `AdminPass123!` | `SystemAdmin` | **`Confidential`** (3) | Полный доступ ко всем документам, управлению метаданными, аудиту и серверам |
| **`auditor`** | `AuditorPass123!` | `SecurityAuditor` | **`Confidential`** (3) | Просмотр реестра документов, базы знаний и полного журнала аудита событий ИБ |
| **`user`** | `UserPass123!` | `User` | **`PublicInternal`** (1) | Доступ только к общедоступным регламентам компании (пароли, общие правила) |

## 🌐 Основные разделы веб-интерфейса и API

- **Главный дашборд:** `http://localhost:5000/`
- **RAG-Ассистент базы знаний:** `http://localhost:5000/assistant`
- **Полнотекстовый поиск по базе:** `http://localhost:5000/search`
- **Реестр документов и загрузка:** `http://localhost:5000/documents`
- **Журнал аудита безопасности:** `http://localhost:5000/audit`
- **Состояние сервисов (Telemetry):** `http://localhost:5000/status`
- **Health Check Endpoint:** `http://localhost:5000/health`
- **Форма авторизации:** `http://localhost:5000/login`

### Ключевые REST API Endpoints:
- `POST /api/v1/auth/login` — аутентификация пользователя (выдача сессионного токена).
- `GET /api/v1/documents` — получение списка документов с учетом прав доступа.
- `POST /api/v1/documents/upload` — безопасная загрузка и автоиндексация файла.
- `GET /api/v1/documents/{id}/download` — скачивание с проверкой прав.
- `GET /api/v1/search?query=...` — ранжированный полнотекстовый поиск.
- `POST /api/v1/assistant/ask` — запрос к RAG-Ассистенту.
- `GET /api/v1/assistant/status` — проверка статуса инференса локальной LLM.

## 📂 Структура синтетических документов для тестирования

В каталоге `sample_data/` подготовлен комплект синтетических регламентов для демонстрации разграничения доступа:

- `sample_data/password_policy.md` (`PublicInternal`) — регламент паролей (доступен всем).
- `sample_data/incident_response.md` (`Restricted`) — регламент реагирования на инциденты SOC.
- `sample_data/server_infrastructure.md` (`Confidential`) — регламент доступа к боевым базам данных и Bastion-хосту (доступен только `admin` и `auditor`).
- `sample_data/qa_test_suite.md` — таблица эталонных контрольных вопросов и ожидаемых ответов.
